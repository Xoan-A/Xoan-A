## Job Monitor

**A full-stack platform for automatically discovering, processing, and reviewing job opportunities.**

![Frontend Jobs and Filters](https://raw.githubusercontent.com/Xoan-A/Job-Monitor/main/docs/screenshots/Frontend%20Jobs%20and%20Filters.jpg)

This project started as an automation experiment and evolved into a more complete application involving **data ingestion, backend processing, persistence, frontend development, and workflow automation**.

## Cross-Platform Online Classes System

**A distributed online classes platform built around multiple communication protocols.**

This project explores how different applications and services can communicate while providing a unified online-class experience.

The system includes a web client, console client, TCP communication, REST APIs, gRPC services, WebSockets, and RabbitMQ.

### Architecture

![Cross-Platform Online Classes Architecture](https://raw.githubusercontent.com/Xoan-A/Cross-Platform-Online-Classes-System/main/Obligatorio/docs/Architecture%20diagram.png)

### Main Technologies

`C#` `.NET 8` `Blazor WebAssembly` `gRPC` `REST` `TCP` `WebSockets` `RabbitMQ` `Docker`

### What I worked with

* Distributed application architecture
* gRPC and Protocol Buffers
* REST APIs
* TCP client/server communication
* WebSocket-based real-time communication
* RabbitMQ asynchronous messaging
* Authentication and session management
* Blazor WebAssembly
* Docker Compose
* Multiple client types

### What I learned

The main purpose of this project was to understand the differences between communication approaches and how they can be combined within a larger system.

It was particularly useful for understanding concepts such as **synchronous vs. asynchronous communication, real-time connections, service boundaries, and protocol selection**.

**Repository:** [Cross-Platform-Online-Classes-System](https://github.com/Xoan-A/Cross-Platform-Online-Classes-System)
